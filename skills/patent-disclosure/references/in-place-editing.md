# 在既有交底书中定点修改

适用于“直接修改这个文件”“在原文件中修改，不必生成新文件”。该要求意味着修改实际原稿，而不是只在聊天给出替换稿，或交付另一个同名系列版本。

## 选择正确版本

1. 核对绝对路径、真实文件格式、当前正文与目标段落；以用户点名的文件为准。
2. 文档若在 Word/WPS 中打开，先检查目标文档是否有未保存编辑。优先使用可用的文档会话或文档接口；受工具环境允许时，可使用应用对象模型读取当前打开版本。
3. 有未保存编辑时，直接在当前文档做定点修改并按原路径保存，保留其他编辑。不要拿旧提取文本、旧备份或磁盘版本覆盖内存版本。无法安全读取或保留时才说明具体障碍并询问，不先关闭文档丢弃修改。
4. 只对精确匹配的目标文档操作。不得为了修改一个文档关闭整个应用、杀掉进程或丢弃其他文档的未保存内容；仅可退出由自己新建且不承载用户文档的实例。
5. 文件被打开而无法独占读取时，先区分应用锁与文件损坏。可改用当前文档接口；内部备份或只读校验可用支持共享读取的接口，必要时对内部快照执行不兼容文件锁的校验器。不要因工具打不开而重建或覆盖原稿。

## 实际修改

- 先读目标及相邻段落，确认替换或插入范围。用标题、内容和位置共同定位，不仅依赖历史段号。
- 多处修订先建立“建议项—原文锚点—替换范围”的对应关系，并在写入前确认每处匹配唯一。一个建议可以涉及多个段落，不能用建议数量代替实际修改范围。
- 应用对象模型与 OOXML 的段落计数可能不同；数学对象的线性化文本也可能含结构字符。不要把 XML 段落序号直接用于应用接口，或把抽取文本中的字符偏移直接当作应用 Range 坐标。优先在已定位段落内查找原有普通文字，再修改实际匹配范围。
- 用户要求增加“第一段”时，在标题后、现有具体条目前插入总述，不把总述替换成第一条具体方案，也不删除后续条目。
- 保留段落标记和原格式，插入正文应沿用相邻正文的样式，不能误继承标题或编号格式。尽可能把一次局部修改作为一个可撤销操作。
- 段落含数学对象时，不能用整段纯文本赋值把公式抹掉。使用能保留数学对象的文档接口，或只修改对应文本节点；跨 run 替换需保留样式边界。
- 只调整公式周围的说明时，保留现有数学对象及公式引导语；不能因替换整段而丢失来源组定义、零分母规则、回退分支、模块回流连接或实施例演算。修改建议给出的段落不是可以直接覆盖所有相邻内容的授权。
- 原生 OMML、上下标、分式、求和、图像关系、表格、节设置和页眉页脚均是应保护的文档对象。除用户授权范围或修复所必需，不顺带改其他章节。
- 如采用临时校验稿再替换原路径，替换前核对源内容或哈希且确认无新未保存编辑；有变化则重新合并。只关闭和重新打开精确匹配且已保存的目标文档。
- “不生成新文件”时不交付新的 Word 副本。必要校验材料留在内部工作目录；不要为每次措辞修改堆积一批新命名版本。

## 验证与交付

1. 验证目标文字已插入或替换，段落数变化符合预期，新增段没有重复。
2. 对比目标与非目标段落，确认只有预定范围发生内容变化。公式不能仅核对数量，还应逐一比较内容；不应改变的数学对象可进一步比较规范化 XML。图像、表格、样式及章节结构应与修改前相符。纯 OOXML 定点编辑可以比较未修改部件字节；应用保存可能重序列化 XML、增加空属性或更新元数据，不能仅据字节变化认定内容损失。
3. 按所用 Word 技能执行结构校验和渲染检查，确认跨页、图题和公式未损坏。已逐页核验的页图若与本次输出逐字节相同，可复用核验记录；其余页面逐页检查，不以单看首页代替。
4. 确认实际原路径已保存，不把“脚本成功”“生成了替换文本”当成完成。最终简述改动和验证，使用文档技能要求的文件引用，只指向最终原文件，不交付内部脚本、PDF 或页图，除非用户索要。

校验器出现警告时，与修改前快照比较，识别既有警告和新增问题。对本次造成的内容或排版缺陷修复后再交付；既有且不影响本次修改的警告不作为擅自重排整篇文档的理由。运行环境和渲染路径遵循当前 Word 技能及依赖加载结果，不把某台机器的临时脚本或软件安装路径写成固定前提。
