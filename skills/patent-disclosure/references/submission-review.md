# 技术交底书提交前审查

目标是判断材料能否交给专利代理机构继续撰写，而不是把交底书当成已提交的申请文件，也不等同于授权预测。采用严格但不过度苛刻的标准。用户只要审查时出具意见，不直接修改原文。

按实际技术领域选用检查项。图模型、训练标签、证据门控及参数冻结的检查只用于包含这些机制的方案；装置、机械、电路或工艺项目改查其真实结构、控制或作用关系，不为套用清单加入算法。

## 审查覆盖与证据

- 完整读取当前版本的正文、所有数学对象、表格、全部附图和图注后再下结论；旧稿、局部截图或历史审查结论不能替代本轮原稿。
- 建立内部定位记录：章节／步骤、段落开头、公式所在位置、图号；需要页码时以当前渲染核实。原文未编号的公式可在报告中临时标识，说明并非原稿编号。
- 每项问题要有原文或可读图像依据。区分明确错误、需满足条件才能成立、需发明人确认，以及仅可选优化。不可从“没写某句话”直接推断实现一定错误。
- 保持问题、方案、效果及实施例之间的对应，不要求补无必要的公式、实验、代码、附图或独立章节。无需修改的部分明确说明。

## 实质检查

### 完整性与流程

核对名称、领域、背景及现有不足、目的、技术方案、效果、实施例、附图说明、适用的替代方案。章节可以合并；非必需章节缺失不自动判不合格。

沿实际方案的输入、处理、控制或结构关系追踪到输出。算法项目再核对预处理、图构建、模型、证据、训练与推理，固定／训练边界及任务头来源；其他领域核对对应的组成、动作或工艺步骤。检查条件不满足时的分支，判断新增机制是否真正改变处理过程，而非只增加名称。

### 公式专项

逐一核验所有数学对象，包括行内符号和算式，不能只看居中公式。统计时区分“数学对象数量”和“独立算法公式数量”，单独一个变量不能计为一套独立技术公式。

核对：

- 变量、上下标、索引集合、取值范围及同符号的上下文；相邻公式的输出能否供下一式使用。
- 标量／向量／矩阵维度，矩阵乘法、转置、路由输入及任务头的维度。
- 求和和归一化方向，分母为零、空集合、无邻居、缺失标签及不可用证据的处理。
- 阈值在哪个得分上生效，截断和加权是否改变得分范围，门控是否被错误解释成预测概率。
- 多来源支持聚合之前是否处理已确认冲突，最大支持值是否掩盖其他有效来源中的未消解矛盾；证据检索范围、候选对象范围和提示注入范围是否被混为一谈。
- 冻结参数仍可传递输入梯度；训练更新公式、优化器描述和图中梯度边界是否一致。示意公式与具体 Adam 实现不能误当作逐步完全相同的更新式。
- 示例算术、参数数量及计数范围；区分共享参数、每场景适配参数、源阶段基础头与部署时的参数。
- 参数下标、独立存储范围与实例核算是否一致；共享路由矩阵及偏置和按类型／任务独立的提示基向量需要分开核对。同一门控幅度不代表不同类型节点使用同一组提示基向量。

对确有问题的公式给位置、原式、问题、修正式、变量定义和修改原因。条件未知时先写成立条件或需确认事项，不直接判错。若原式与正文定义联合起来已经明确，不为追求形式重新造公式。

### 附图专项

逐图读取全部框、连线、图例、注释及公式，并逐一核对正文图引用；大图局部放大。仍无法读取的区域说明无法核实，不能猜测。使用 [figures.md](figures.md) 的连线与边界检查。

重点查新增或空白模块、门控旁路、冻结与梯度混淆、图中文字沿用旧版、训练与在线混画，以及“零门控”和“无有效版本”的条件是否相同。正文已经能解释的简化表示不强制展开。图名长短不同但指向同一技术内容，不轻率判为图号错误。

### 实施例与事实状态

- 检查实际场景、输入记录、对象关联、参数、关键执行过程及输出形式，不能仅重复功能目标。
- 构造示例可以支持技术理解，不必伪造一个业务概率或性能提升比例来充数。没有真实对比实验也不自动等于不能交底。
- 明确真实实测、构造示例和预期效果。来源质量配置、超参数起始值及精确参数核算不是实测准确率。
- 检查实例是否符合公式、标签及版本口径，有无未交代的新模块。评价时关注训练标签成熟时点、时间切分和未来信息可用性，但将未确认的执行情况与已证明的泄漏区别表述。

### 专利写作及初步授权风险

从技术问题、技术手段及技术效果整体分析算法与具体场景、数据处理和模型计算的联系；检查公开充分性、保护范围及新颖性／创造性风险。必要实现细节要交代，常规实现无需写成完整代码说明书。

对模型名、数据集、具体参数的唯一限定，区分真正必要条件和基础实施方式；不要为扩大范围删掉发明赖以成立的技术机制。技术模块的常规性不能单独决定组合有无创造性。

涉及现行中国法律或审查口径，核实国家知识产权局等官方原文及生效时间；引用简要、贴近相关判断。若仅核对法律规则而没有做专利／非专利文献的系统现有技术检索，必须如实说明，不宣称已经排除新颖性或创造性风险。交底成熟度评分不是审查结论。

核对全文名称、术语、符号、步骤、图表及公式引用、重复或遗留内容、绝对化表述。常见技术缩写无需强制全部翻译；措辞可更优美不构成必改缺陷。

## 评估并落实已有修改建议

适用于用户提供上一轮意见并要求“判断是否合理，合理就修改”。按建议处理相关范围，不自动重做完整评分报告，也不机械认定所有意见都成立。

1. 对照当前原文及相邻公式、实施例和附图，判断建议是修复技术矛盾、消除歧义、可选完善，还是引入未经支持的新设计；保留原方案已有的成立条件。
2. 建议写“需先确认实际设计”时，先检查参数下标、正文定义、实例配置和参数核算是否已能共同确定。证据一致即可明确，不重复询问；存在多种同样可能且影响实现或核算的设计时，列出确切分歧，继续处理不依赖该选择的其他项。
3. 用户已授权合理修改时直接落实，不停在给出替换稿或再次请求确认。意见标为“可选”而用户同时要求合理则改，可在该授权范围内一并处理；不得扩展为无关章节重写。
4. 替换前列出必须保留的定义、输入输出连接、公式、数值演算及回退分支。建议段落省略这些内容时，采用局部替换或合并说明，不能照抄导致信息丢失。原位修改按 [in-place-editing.md](in-place-editing.md) 执行。
5. 技术效果仅写现有方案能支持的机制性作用。参数组织与精确核算可以说明更新或存储范围，不能据此推断未经实测的准确率、训练速度或业务收益。

完成后简述哪些意见已采纳、哪些有不同判断及依据；若均已落实，不必重复整份审查意见。关键设计取舍和验证结果需要在最终答复中说清。

## 完整提交前审查报告格式

用户要求完整提交前审查且未另定格式时，依以下七部分组织。更具体的用户格式优先；简评不必机械展开全套表格。

### 1. 总体结论

先直接回答是否能提交给专利代理机构，选择：

- **A：可以提交**——核心方案完整，未发现影响交底的重大问题。
- **B：修改后提交**——整体基本完整，有应先修正的实质问题。
- **C：暂不建议提交**——有核心缺失、明显矛盾或关键实施信息不足。

主要原因不超过200字。等级依据问题的重要性，不按分数机械划线；一般性 P2 或可选建议不自动把 A 降为 B。交底可提交不代表正式申请合格或必能授权。

### 2. 分项审查评分

| 审查项目 | 满分 |
| --- | ---: |
| 文档整体完整性 | 10 |
| 核心技术方案完整性 | 25 |
| 技术原理与数学公式（无公式时核对机理及参数） | 15 |
| 附图与正文一致性 | 10 |
| 实施例充分性 | 15 |
| 创新点及专利撰写风险 | 15 |
| 全文语言与细节规范 | 10 |
| 总分 | 100 |

为各项给实际得分和依据，核对加总。完整性、技术、公式和图的已通过事项也要有依据；可在本节附紧凑的公式核验表和逐图结论，保持七部分结构。不能用漂亮的格式分掩盖核心不可实施问题。

### 3. 必须修改的问题

| 序号 | 问题位置 | 原文内容 | 存在的问题 | 修改建议 | 严重程度 |
| --- | --- | --- | --- | --- | --- |

- **P0**：严重，影响核心理解或可实施性。
- **P1**：重要，应在提交前处理。
- **P2**：一般，不影响整体交底，建议完善。

先列 P0／P1，注明是技术缺陷、撰写风险还是表达歧义。若无必改问题直说“未发现”，不能为填表凑问题。纯可选优化移到第6节。

### 4. 可以直接替换的修改内容

每项按 **【修改位置】【原文】【建议修改为】【修改原因】** 给出，保持技术思想。涉及信息不足时写“需发明人补充”并列确切缺项，不把猜测写入可直接替换稿。图的修改给现有框名、连线及建议标签。

### 5. 需要发明人确认的问题

仅列文档及本轮证据无法解决的技术选择、参数依据、模块关系、实施和效果事实。无需再次追问已明示为构造示例的数据是否真实；没有实测时不要求补虚构数据。已授权补全为基础设计的内容，与声称已经实际采用的实现分开核实。

### 6. 可选优化项

列不影响交底提交的少量改进；明确无需大规模重写或增加无必要图表。避免把本节事项又作为第1节降级的理由。

### 7. 最终提交检查清单

检查结果限“通过／未通过／待确认”，在备注解释实质依据：

| 检查项目 | 检查结果 | 备注 |
| --- | --- | --- |
| 核心技术方案完整 | | |
| 技术步骤逻辑一致 | | |
| 数学公式无明显错误 | | |
| 关键变量定义完整 | | |
| 附图与正文一致 | | |
| 实施例能够支撑技术方案 | | |
| 创新点得到具体技术方案支持 | | |
| 技术效果表述合理 | | |
| 全文术语与编号统一 | | |
| 不存在明显无关或遗留内容 | | |

最后明确写 **“最终建议：可以直接提交／完成指定修改后提交／暂不建议提交。”** 若需修改，只列必须完成的最少事项。审查结论、等级、评分、问题严重度和清单之间应一致。
